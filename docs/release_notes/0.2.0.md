# Release notes — mcp-memory 0.2.0

Shipped 16 November 2026.

One store process now serves every harness and the CLI. You can import the memories you already have in Kiro. Agents must name the repository they are working in. Content may be up to 20 KiB. The project is MIT-licensed.

## Highlights

### One store for every harness

Helix allows a single writer per database. In 0.2.0, `mcp-memory` with no subcommand (and every CLI command) talks to a shared `mcp-memory daemon` over a Unix socket in the data directory's `run/` folder. The first client starts it; it exits after an idle period (`MCP_MEMORY_IDLE_SECS`, default 300). Cursor, Claude Code, Codex, Kiro-as-client, and the CLI can all use the same store at once.

### Import from Kiro

```bash
mcp-memory import-kiro
# or
mcp-memory import-kiro --path /path/to/memories.db
```

Reads `~/.kiro/memories/memories.db` (or `$KIRO_HOME/memories/memories.db`). Kiro ids are kept, so re-running is safe. `USER_PREFERENCE` maps to `preference`; other Kiro types map to `fact`. `Global` and `repo:…` scopes map onto ours. Kiro repo keys (for example `github/owner/repo`) may need a `repo_overrides` pin to match a local checkout.

### Repository path is required

Pass `project_path` (absolute path of the repository in play) on `memory_recall` and `memory_remember`. The server does not guess a repository from its own working directory. Without a path, recall returns only global memories, and a write is stored as global even if the agent asked for `scope: repository` (the result then includes a note).

### Larger statements

The content cap is **20 KiB** (was 4 KiB), so longer Kiro-style facts import and store intact.

## Upgrade

1. Build and install the new binary:

   ```bash
   cargo build --release
   install -m 0755 target/release/mcp-memory ~/.local/bin/mcp-memory
   ```

2. Stop any old store process (or wait for idle exit), then reconnect the harness so it picks up the new binary.

3. Optionally import Kiro memories: `mcp-memory import-kiro`.

Existing data in the Helix directory is unchanged. Full usage is in [docs/usage.md](docs/usage.md). The detailed change list is in [CHANGELOG.md](CHANGELOG.md).
